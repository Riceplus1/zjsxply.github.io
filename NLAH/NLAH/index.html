Abstract

Abstract

Agent performance is strongly shaped by the surrounding harness: the external execution system around a model that organizes a task run. Yet this logic is usually buried in tightly coupled controller code, which makes harnesses hard to inspect, compare, transfer, and ablate. This paper asks whether the reusable design pattern of an agent harness can be represented as an executable natural-language object.

We introduce Natural-Language Agent Harnesses (NLAHs), editable documents that describe run-level harness policy, and Intelligent Harness Runtime (IHR), a shared runtime that interprets these documents into agent calls, handoffs, state updates, validation gates, and artifact contracts. Across coding, terminal-use, and computer-use benchmarks, IHR-executed NLAHs achieve comparable task outcomes to code and prompted realizations, while exposing much shorter static harness policies. Module ablations further show that explicit harness modules are analyzable.

Readable Policy

Harness policy compressed from thousands to hundreds of tokens — inspectable at a glance.

Shared Runtime

IHR executes NLAHs across coding, terminal, and GUI benchmarks under common semantics.

Analyzable Modules

Explicit modules support clean ablation — revealing what actually drives agent performance.

Overview

Three Ways to Control an Agent Run

The spectrum ranges from rigid code control to fully autonomous self-harnessing. NLAH+IHR sits in the middle — keeping policy readable while remaining executable under a shared runtime.

Method

NLAH + IHR Framework

Separating harness policy from mechanism — the core design that makes agent harnesses into inspectable, editable, and executable objects.

4

Scripts & Adapters

Deterministic code for exact operations — test runners, parsers, validators, benchmark wrappers, sandboxing. Kept in code because they require precision.

3

NLAH

The per-harness policy document.

Editable natural language that specifies stages, roles, state rules, verification gates, recovery rules, and stopping conditions. This is what changes from one harness to another.

2

Runtime Policy / Charter

Shared execution semantics.

A fixed instruction that defines how IHR interprets NLAHs — parent-child boundaries, artifact semantics, completion gates, and audit requirements.

1

Base Agent

Minimal executable substrate — an LLM loop with terminal access. Can read/write files, run processes, record events, and launch child agents.

State & discipline win: File-backed state and self-evolution are the strongest modules — they tighten the path from intermediate work to auditable evidence and final benchmark acceptance.
More branching ≠ better control: Multi-candidate search produces the largest topology change (5.7 agent calls on SWE) but yields a net negative (−1.6%). Extra process layers without acceptance alignment can hurt.
Compression is risky: Context compression hurts both benchmarks. Durable path-addressable state (file-backed) is a more reliable carrier than aggressive summarization.
Conclusion

Conclusion

Harness policy can be externalized into compact, executable, and analyzable natural-language objects — turning incidental glue around models into scientific representation objects.

1

NLAHs make harness policy explicit as editable natural-language documents — readable, portable, and module-structured.

2

IHR provides shared execution semantics that turn NLAH text into auditable agent calls, handoffs, state, and verification gates.

3

Competitive outcomes across coding, terminal-use, and computer-use benchmarks — NLAH performance is in the same regime as code harnesses.

4

Module-level analysis is feasible once harness modules are explicit — enabling a scientific approach to harness design.
